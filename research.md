Цель сайта: рассказать о Доме Капибара и продать билет на посещение.
Дата исследования: 2026-10-10. Три агента работали параллельно.

**Честная оговорка.** Агенты имели только текстовый доступ к сайтам. Цвета и шрифты чужих сайтов они почти не смогли подтвердить, а авторитетных статей Awwwards и CSS-Tricks с трендами 2026 не нашли. ## 2. Структура лендинга: идеальные 7 блоков

**Что проверено:** Skypark Сочи ([skypark.ru](https://www.skypark.ru/)) разобран напрямую; обзор событийных лендингов [checkoutpage.com](https://checkoutpage.com/blog/high-converting-event-landing-page-examples); общие руководства ([SendPulse](https://sendpulse.com/ru/blog/selling-landing-page), [Unisender](https://www.unisender.com/ru/blog/kak-sdelat-landing/), [GetCourse](https://getcourse.ru/magazine/prodayushiy-lending)); Tilda по обзорам [Lifehacker](https://lifehacker.ru/tilda-review/) и [Callibri](https://callibri.ru/blog/kak-sozdat-sayt-na-tilde) (550+ блоков, редактор Zero Block). **Не удалось:** каталог шаблонов Tilda (404), список сайтов на onepagelove (получен один пример: [Select26](https://onepagelove.com/select26), IT-конференция).

**Типичные блоки продающего лендинга:** первый экран (заголовок, описание, CTA), выгоды, соцдоказательства (отзывы, настоящие фото), финальный CTA. У сайтов продажи посещений дополнительно: карточки с ценами, расписание, FAQ, правила и возврат в подвале.

**Сквозные правила:** залипающая компактная шапка с якорями и кнопкой «Купить билет»; на мобильном залипающая панель «Купить билет от X ₽»; одна главная цель — покупка.

Структура ниже — **рекомендация** (предположение, собранное из подтверждённых паттернов).

| # | Блок | Содержимое | CTA | Мобильный UX |
|---|---|---|---|---|

## 3. Тренды 2026: 5 решений для применения

**Что проверено:** Awwwards Sites of the Day показал только названия и теги (Animated, Scrolling, Microinteractions, Single page, WebGL, GSAP, Three.js), то есть популярность GSAP, скролл-анимаций и микроинтеракций. MDN: `animation-timeline` не входит в Baseline. **Только по сниппетам поиска:** обзоры [reallygooddesigns](https://reallygooddesigns.com/web-design-trends-2026/), [wannathis.one](https://wannathis.one/blog/web-design-trends-2026), [firebrandagency](https://www.firebrandagency.com/blog/web-design-trends-2026), [ionos](https://www.ionos.com/digitalguide/websites/web-design/webdesign-trends.md). **Не найдено:** авторитетных статей Awwwards и CSS-Tricks про тренды 2026. Блоги расходятся в версиях браузеров для scroll-driven animations и View Transitions — **перед внедрением сверить caniuse/MDN и сделать fallback.** Детали API (GSAP, Lenis) — знания агента, сверять с документацией.

### 1. Scroll-driven анимации на CSS
Появление карточек и лёгкий параллакс облаков и листьев через `animation-timeline: view()`, без JS.
```css
@media (prefers-reduced-motion: no-preference) {
  @supports (animation-timeline: view()) {
    .reveal { animation: rise linear both; animation-timeline: view(); animation-range: entry 0% cover 30%; }
  }
}
@keyframes rise { from { opacity: 0; translate: 0 40px } to { opacity: 1; translate: 0 0 } }
```
Риски: анимировать только `transform` и `opacity`; без поддержки контент должен быть виден (или fallback на GSAP ScrollTrigger). Источник: [MDN](https://developer.mozilla.org/en-US/docs/Web/CSS/animation-timeline).

### 2. Выразительная крупная типографика
Огромное название «Дом Капибара» в hero: `font-size: clamp(2.5rem, 8vw, 7rem)`, `text-wrap: balance`, `font-display: swap`. Риски: только нужные веса и кириллическое подмножество (LCP), контраст от 4.5:1, побуквенные анимации отключать при reduced-motion, полный текст в `aria-label`. Источник: обзоры по сниппетам (уровень уверенности ниже).

### 3. Тёплые «человечные» цвета, текстура, органичные формы
Мягкие тёплые тона, лёгкое зерно, `border-radius` 24–40px, волнистые SVG-разделители секций, ручные иллюстрации. Риски: тяжёлые фильтры и blur, текстура должна быть статичной и лёгкой; проверять контраст. Источник: reallygooddesigns и wannathis.one (по сниппетам).

### 4. Плавный скролл и микроинтеракции (Lenis + GSAP ScrollTrigger)
Живая кнопка «Купить билет», наклон карточек капибар при наведении (`@media (hover:hover)`). Теги Microinteractions, Scrolling и GSAP заметны на Awwwards (проверено). Риски: плавный скролл может мешать якорям и клавиатуре, на мобильных обычно не включают, при reduced-motion отключать; GSAP ~30–40 КБ, грузить лениво.

### 5. View Transitions и лёгкие интерактивные элементы
`document.startViewTransition()` для переключения вкладок «Билеты / Расписание» и пересчёта цены; `<details name>` для FAQ, `<dialog>` для модалки бронирования.
```js
if (document.startViewTransition) document.startViewTransition(update); else update();
```
Риски: в пределах одного документа поддерживается в Chrome/Edge 111, Safari 18, Firefox 144 (Chrome for Developers), но для старых версий нужен fallback; при reduced-motion отключать (`::view-transition-group(*) { animation: none }`); для `<dialog>` и вкладок — фокус и ARIA.

**Общее:** `prefers-reduced-motion`, `:focus-visible`, семантика и `alt`, `loading="lazy"`, WebP/AVIF, `width/height` против сдвигов, зоны касания от 44px, LCP до 2,5 с на мобильном.

**Минимальный набор:** тренды 1, 2, 3 и 5. Lenis и WebGL — только при запасе по производительности.

## 6. Экспертная оценка

Три независимых аудита с проверкой фактов: UX-дизайнер, маркетолог-конверсионист, потенциальный клиент (владелец бизнеса с семьёй в Сочи, телефон). Метки: **[И]** проверено источником, **[П]** виден только сниппет поиска, **[М]** мнение/предположение эксперта. Данных о самом доме у экспертов нет, поэтому цены, форматы и рейтинги помечены как [ВСТАВИТЬ].

### 6.1. Главный вывод: юридический и этический риск формата

Самый заметный пропуск в разделах 1–5; его нашли сразу два эксперта.

- **[И/П]** Закон 498-ФЗ «Об ответственном обращении с животными» (в силе с 01.01.2020) не содержит термина «контактный зоопарк». Ограничение выводится из ст. 15: не допускаются мероприятия, **основная цель** которых физический контакт посетителей с животными. Если контакт не основная цель, деятельность допустима при условии, что у животных есть недоступная для людей зона с укрытиями. Для культурно-зрелищного использования животных нужна лицензия. Источники: [Pravoved](https://pravoved.ru/journal/kontaktnye-zooparki/) (номер закона в статье указан неверно — «458»; 498-ФЗ приведён по другому сниппету и по памяти, сверить на pravo.gov.ru), [Консультант](https://www.consultant.ru/law/podborki/kontaktnyj_zoopark/), [360.ru](https://360.ru/tekst/ekologiya/zverskij-biznes/).
- **Не подтверждено:** действующая редакция закона и статус упомянутого в выдаче законопроекта 2026 года (даты противоречивы). Нужен юрист.
- Критика зоозащитников (стресс, тесные клетки, укусы, отсутствие ветсертификатов) — репутационный риск; сайт не должен его провоцировать.
- **Следствие:** заголовок «погладить, покормить, сфотографировать» **рискован** и юридически, и репутационно. Что реально разрешено, решает владелец дома вместе с юристом, а не копирайтер.

### 6.2. Эксперт 1 — UX-дизайнер

**Слабые места предложенной структуры [М]**
- Блоки 3 (расписание) и 4 (билеты) дублируют друг друга: это один выбор «дата → сеанс → тариф». Расписание лучше сделать частью виджета билетов, а отдельный блок оставить для «формата визита».
- Отзывы стоят после «Как добраться», а доверие нужно **до** покупки. Порядок лучше: hero → что ждёт → отзывы (коротко) → билеты → как добраться → FAQ.
- Правила и возврат спрятаны в блок 7, а для билета они критичны: краткая строка «возврат / перенос / дети с N лет» должна стоять рядом с кнопкой оплаты.
- Вторая кнопка «Как добраться» в hero конкурирует с главным CTA; достаточно ссылки в шапке. Строка доверия в hero бессмысленна, пока нет реальных цифр.
- Карусели в блоках 2 и 6 лишние: хватит сетки из 3–6 карточек.
- «Осталось N мест» — только если данные реальные из билетной системы.

**Пропущено [М]:** цена «от X ₽» в hero и в залипающей кнопке; блок про заботу о животных (правила, режим отдыха, ветеринар); альтернатива онлайн-оплате (телефон, мессенджер); статус «открыто сегодня до N»; гостевая покупка без аккаунта; юридическая строка (ИНН, оферта, политика данных, 54-ФЗ — проверить юристом); страницы ошибки оплаты и подтверждения (письмо/SMS с QR); SEO-разметка LocalBusiness и Open Graph; цели Яндекс.Метрики.

**Типичные ошибки новичков [М]:** красивое поверх понятного (анимированный hero без цены и кнопки); цена спрятана до последнего шага; 10+ блоков вместо одной цели; стоковые фото (для живых животных особенно заметно); нет проверки на реальном телефоне со слабой сетью; тексты не отвечают на «где, сколько, с кем, что с собой».

**Что обязательно на лендинге продажи билетов**
- Цена и кнопка в первом экране [М; совпадает с паттернами из раздела 1].
- Итоговая цена без сюрпризов: 39% покупателей бросают оформление из-за дополнительных сборов [И: [Baymard](https://baymard.com/blog/reduce-cart-abandonment)].
- Гостевая покупка: 19% бросают, если вынуждают создать аккаунт [И: Baymard].
- Простое оформление: 18% бросают из-за сложного процесса [И: Baymard]. Минимум полей: имя, телефон, e-mail.
- Адрес, часы, как попасть, телефон; что включено, возраст, длительность, правила, возврат [М].
- Настоящие фото и отзывы с источником (Яндекс Карты, 2ГИС) [М].
- Скорость: LCP ≤ 2,5 с, INP ≤ 200 мс, CLS ≤ 0,1 на 75-м процентиле [И: [web.dev](https://web.dev/articles/vitals)].
- Цифры Baymard во вторичных источниках расходятся (48–49% для сборов, 24–35% для аккаунта); взята текущая страница Baymard.

**Что раздражает пользователей**
- Попапы и наложенные оверлеи на мобильном, случайное закрытие [П: NN/g — [Popups](https://www.nngroup.com/articles/popups/), [Overlay Overload](https://www.nngroup.com/articles/overlay-overload/)]; прочитаны только сниппеты, даты размыты.
- Блоки «акция/купон», похожие на рекламу, игнорируются — баннерная слепота [П: [NN/g](https://www.nngroup.com/articles/banner-blindness-old-and-new-findings/)].
- Движение при скролле и параллакс вредят людям с вестибулярными нарушениями [И: [WCAG 2.2 SC 2.3.3](https://www.w3.org/WAI/WCAG22/Understanding/animation-from-interactions.html), уровень AAA].
- Scroll-hijacking: описан в блогах как нарушение ожиданий и проблема для вспомогательных технологий [П: [Front-End Checklist](https://frontendchecklist.io/rules/accessibility/scrolljacking)]; статью NN/g по теме найти не удалось.
- Мелкий текст на мобильном (база от 16 px), автовидео со звуком, автокарусели, куки-баннер на пол-экрана, чат-виджет поверх кнопки оплаты, три залипающих элемента сразу (шапка + нижняя панель + чат): оставить не более двух [М].

**Риски выбранных трендов**
- **Lenis [М]:** выигрыш для продажи билетов невелик, а риски (якоря, клавиатура, укачивание, вес, конфликты со скроллом календаря) реальны. **Рекомендация: отказаться.** Если оставлять — выключать при `prefers-reduced-motion`, на сенсорных экранах и внутри виджета билетов.
- **Scroll-анимации [М]:** контент по умолчанию должен быть виден; анимация только внутри `@supports` и `prefers-reduced-motion: no-preference`; не сдвигать кнопку покупки и календарь (CLS); анимировать только `transform` и `opacity`.
- **View Transitions [И: [Chrome for Developers](https://developer.chrome.com/docs/web-platform/view-transitions)]:** внутри одного документа (`document.startViewTransition`) поддерживается в Chrome и Edge 111, Safari 18, Firefox 144; между документами Firefox не поддерживает. Для одностраничника подходит первый случай, на старых версиях нужен fallback. Использовать только для декоративных смен (вкладки), не для пересчёта цены; итоговую сумму объявлять через `aria-live`. Раздел доступности на странице Chrome проверить не удалось, поэтому reduced-motion прописывать явно.

### 6.3. Эксперт 2 — маркетолог-конверсионист

**Оффер.** Реальных данных о доме нет, поэтому варианты с плейсхолдерами:
1. «Час с капибарами в Сочи» / [длительность], [адрес/район], дети от [возраст], билет от [цена] ₽.
2. «Дом, где живут капибары. Приходите в гости» / небольшие группы, спокойный формат, [что включено], выбор времени и оплата онлайн.
3. «Самый спокойный зверь в Сочи ждёт вас» / как встретиться с капибарами: [формат], для семей с детьми от [возраст].
4. «Сфотографируйтесь с капибарой: у нас это можно» — **только при подтверждённом разрешении**.
5. «Капибары в Сочи: билет за минуту» / сеансы [часы], группа до [N] человек.

**Выбор [М]:** вариант 2 основной, вариант 1 запасной для A/B-теста. «Дом» и «в гости» отличают от парка («Капибары и друзья») и зоопарка («Рио»), звучат мягче «погладить/покормить» и не обещают потенциально запрещённого. Вариант 1 конкретнее и лучше для трафика по запросам «капибары Сочи». На первом экране родитель ищет четыре ответа: что, где, с какого возраста, сколько. Без подтверждения не использовать «единственные в Сочи», «лучшие», «100% безопасно». CTA: «Выбрать дату и время».

**Триггеры доверия (по приоритету) [М]**
1. Настоящие фото и короткое видео без звука из дома: капибары, гости, персонал. Без стока.
2. Рейтинги Яндекс Карт и 2ГИС со ссылкой на карточку — только реальные цифры.
3. Блок «Как мы заботимся о капибарах»: ветеринар, режим отдыха, лимит группы, зона, куда животное может уйти. Работает и как доверие, и как этическая защита.
4. Безопасность гостей: гигиена, правила для детей, аллергики.
5. Оплата и возврат рядом с кнопкой (СБП, карты, отмена, дождь, закрытие сеанса), чек по 54-ФЗ.
6. Реквизиты, оферта, политика данных, телефон и мессенджеры в подвале.
7. 3–6 настоящих отзывов с именем и датой, с разрешения авторов.

**Закон и реклама**
- **[И]** По 38-ФЗ интернет-реклама маркируется (ст. 18.1, токен через ОРД), ответственность — ст. 14.3 КоАП ([Гарант](https://www.garant.ru/article/1421318/)). Контекст, посевы и блогеры маркируются; сам сайт-визитка обычно информация о компании, но граница тонкая [М].
- **[М, текст закона поиском не подтверждён]** Ст. 32 ЗоЗПП: право отказаться от платной услуги с оплатой фактических расходов; условия возврата в оферте не должны ей противоречить. Превосходные степени требуют подтверждения. Согласие и политика по 152-ФЗ.
- Всё перечисленное согласовать с юристом.

**Этика [М]:** не подавать капибар как «игрушку»; не обещать «обнимашки по желанию»; лимит гостей и время сеанса; зона отдыха без людей; без вспышки и криков; фото и видео на сайте без стресса для животных.

**Воронка и измерение** (цель — оплаченный заказ, а не «заявка»; заявка остаётся запасным путём для групп и школ)

| # | Шаг | Где отваливаются | Событие в Метрике |
|---|---|---|---|
| 1 | Заход | Медленная загрузка, неясный оффер | Визит, скорость, отказы |
| 2 | Прокрутка | Hero не отвечает на вопросы | Scroll 50% / 75% |
| 3 | Клик «Выбрать дату» | Не видна кнопка, нет цены | `cta_hero_click`, `cta_sticky_click` |
| 4 | Выбор даты и времени | Нет мест, сложный календарь | `ticket_date_selected`, `ticket_qty_changed` |
| 5 | Начал оформление | Много полей, неясный возврат | `checkout_start` |
| 6 | «Оплатить» | Нет СБП, ошибка оплаты | `pay_click` |
| 7 | Оплата прошла | Банк, 3-D Secure | **`purchase`** (с суммой) |
| 8 | После покупки | Не пришёл билет, не нашли место | `ticket_delivered`, клик «Как добраться» |

- **[И]** Цели Метрики — «JavaScript-событие», вызов `ym(ID, 'reachGoal', 'цель', {параметры})`; счётчик должен подключаться раньше вызова целей ([справка Яндекса](https://yandex.ru/support/metrika/objects/reachgoal.html)). Цель покупки вызывать на странице подтверждения оплаты с суммой.
- **[М]** Ключевые метрики: конверсия визит → покупка; клик по CTA → оплата; доля мобильных; конверсия по источникам; доход на визит; клики «Позвонить» и «Маршрут». Вебвизор и карта кликов со старта; UTM на все платные и партнёрские ссылки; учитывать возвраты. При малом трафике A/B-выводы недостоверны (ориентир — 100+ покупок на вариант, практика, не источник).

**Бенчмарки [И, с оговорками]**
- Брошенные корзины в среднем 70,22% по 50 исследованиям (на 22.09.2025); применимость к билетам условная ([Baymard](https://baymard.com/research/cart-abandonment-rate)).
- 53% посетителей уходят, если мобильная страница грузится дольше 3 с — исследование Google 2017 года, устарело, но направление подтверждается ([Think with Google](https://thinkwithgoogle.com/_qs/documents/57/mobile-page-speed-new-industry-benchmarks.pdf)).
- Доля мобильного трафика 77% (отчёт вендора Quantum Metric за 2025, методика не раскрыта; [источник](https://www.quantummetric.com/test-benchmark)).
- Конверсия e-commerce около 2,7% — вторичный блог, только порядок величины ([RedStag](https://redstagfulfillment.com/average-conversion-rate-for-ecommerce/)). Цифры 10–13% для лендингов (блоги NudgeNow, Flint) расходятся с предыдущей и в план закладывать не стоит.
- **Не найдено:** бенчмарков по продаже билетов в зоопарки/на аттракционы и по российскому мобильному трафику; реалистичную цель даст только собственный трафик.

### 6.4. Эксперт 3 — потенциальный клиент (владелец бизнеса, семья, телефон)

**Первые 5 секунд**
- **[П]** Решение «уйти или остаться» принимается примерно за 10 секунд, средний визит около 30 секунд (Nielsen, по [зеркалу текста](https://git.captnemo.in/nemo/hn-classics/raw/commit/77c5516696ac35039a307899b9a434a7129ceb5d/_stories/2009/11559811.md) и пересказу [CustomerThink](https://customerthink.com/?p=56953); оригинал на nngroup.com не открывался).
- **[П]** В eye-tracking-работе [Sheng, Lockwood, Dahal 2013](https://scholarsmine.mst.edu/bio_inftec_facwork/684) пользователю нужно около 2,66 с, чтобы начать фиксироваться на элементе страницы. Про 50 мс впечатления от дизайна первоисточника нет.
- Данных о доле мобильного трафика в туризме РФ не найдено — смотреть Яндекс Метрику или отчёты АТОР / Яндекс Путешествий.
- **[М]** Что видно за 5 секунд: фото капибары; заголовок «что это, где, можно ли погладить»; цена «от X ₽» и кнопка; признаки реального места (адрес, рейтинг, фото людей). Если первый экран не отвечает «что, где, сколько, с какого возраста», клиент уходит.

**Проход по 7 блокам [М]**
1. **Hero:** остаюсь при реальном фото, «от X ₽», адресе и возрасте. Закрою, если фото стоковое или тяжёлое (больше 3 с на 4G) или заголовок общий.
2. **Что ждёт:** нужен честный ответ «можно ли трогать, кормить, брать на руки».
3. **Расписание и правила:** здесь бросил бы, если расписания нет или оно картинкой, а правила длинные.
4. **Билеты — главная точка потери.** Закрою вкладку при регистрации, цене только на последнем шаге, отсутствии СБП, мелких кнопках, невидимом возврате, длинной форме. Блок стоит слишком далеко для решения «идём сегодня» — цена и кнопка должны быть уже в hero.
5. **Как добраться:** нужен в первых двух экранах, с временем в пути от центра и Адлера и кнопкой «открыть в Яндекс Картах».
6. **Отзывы:** при их отсутствии лучше ссылка на карточку Яндекс/2ГИС, чем выдуманные; выдуманные распознаются, доверие пропадает.
7. **FAQ и подвал:** здесь проверяется «серьёзность» — ИНН/ОГРН, оферта, телефон, возврат. Без них как владелец бизнеса подумаю «однодневка».

**Профессионализм глазами владельца бизнеса [М]:** доверие дают реквизиты, адрес на карте, живой телефон/мессенджер, быстрая загрузка, отсутствие битых ссылок и опечаток; недоверие — стоковые фото, прыгающий из-за анимаций текст, счётчик «осталось 2 места» без основания.

**Сомнения клиента для FAQ [М]:** аллергия на шерсть; гигиена (руки, антисептик); возраст детей и присутствие взрослых; дождь и закрытие; возврат и перенос; можно ли брать на руки; что делать, если ребёнка укусили; чем кормят и можно ли своё. Красные флаги для зоозащитников: «селфи с животным в руках», «до 100 гостей в час».

### 6.5. Проверка фактов в этом файле

Третий эксперт перепроверил разделы 1–5:
1. **View Transitions.** Формулировка «поддержка противоречива» устарела: в пределах одного документа API поддерживается в Chrome/Edge 111, Safari 18, Firefox 144 (Chrome for Developers). Fallback для старых версий нужен. *Исправлено в разделе 3.*
2. **Scroll-driven animations.** `animation-timeline` не входит в Baseline (MDN), поэтому «без JS» и включение в минимальный набор требуют обязательного `@supports` и fallback. Версии по таблицам MDN/caniuse получить не удалось.
3. **Awwwards.** Теги GSAP, Microinteractions и Scrolling — косвенный довод в пользу тренда, а не доказательство популярности.
4. **«Основные соперники в выдаче».** Не подтверждено: выдачу по запросам не анализировали, официальные сайты «Капибары и друзья» и «Рио» не найдены. *Исправлено в разделе 4.*
5. **Capybara Park (Испания)** — батутный парк; паттерн «правила на видном месте» из него натянут, опору в разделе 1 считать слабой.
6. Тренды 2–3 (типографика, тёплые цвета) основаны только на сниппетах и для конверсии второстепенны.
7. Контраст белого на `#E4572E` около 3,9–4,2:1 — для мелкого текста ниже порога 4,5:1; проверять в WebAIM. Ориентиры «LCP ≤ 2,5 с» и «44 px» корректны (Google Core Web Vitals, Apple HIG).
8. `<details name>` (эксклюзивный аккордеон) в старых браузерах не поддерживается [М] — проверить на caniuse.
9. **Главный пропуск:** в разделах 1–5 не было законодательства и этики содержания животных — см. 6.1. Заголовок в блоке 1 раздела 2 помечен предупреждением.

**Обязательно до запуска**
1. Получить от владельца дома реальные данные: адрес, цены, длительность, возраст, правила, документы, фото и отзывы; заполнить все [ВСТАВИТЬ].

4. Реальные фото и видео без стока; настоящие отзывы либо ссылка на карточки Яндекс Карт и 2ГИС; завести карточки и собрать первые отзывы.

6. Реквизиты, оферта, политика данных, возврат — в подвале и краткой строкой рядом с кнопкой оплаты.

**Структура (правки к разделу 2)**
7. Порядок: hero → что ждёт → отзывы → билеты (с расписанием и выбором сеанса внутри) → как добраться → FAQ с правилами. «Как добраться» с временем в пути и кнопкой «Открыть в Яндекс Картах» — не дальше второго экрана.
8. Цена «от X ₽» и кнопка «Выбрать дату и время» в hero и в залипающей панели; в hero одна главная кнопка.
9. Билеты: итоговая цена без сборов на последнем шаге, покупка без аккаунта, минимум полей, СБП и карты, альтернатива — телефон/мессенджер, QR-билет на почту/SMS, страницы ошибки и подтверждения.
10. «Осталось N мест» — только из реальных данных билетной системы.
11. Без каруселей и автоплея; залипающих элементов не больше двух; без попапов до первой пользы.

**Дизайн и техника (правки к разделам 3–4)**
12. Lenis и WebGL не использовать. Оставить CSS-появление с `@supports` и видимым состоянием по умолчанию, View Transitions только для декоративных смен (вкладки), всё под `prefers-reduced-motion`.

**Измерение**
15. До запуска трафика настроить цели Метрики из таблицы воронки; главная цель — `purchase`. Вебвизор, UTM, отдельные цели «Позвонить» / «Маршрут» / мессенджер; учитывать возвраты.
